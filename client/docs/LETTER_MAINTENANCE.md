# 客户端信件对比与整理

设置中的“导入与导出信件”下方新增“信件对比与整理”，接入社区迁移工具 PR #508 的信件维护用途，不提供版本回退。

## 使用

- **检查当前信箱**：查看完全重复、近似重复、失败或已取消的信件，以及明确带有 `imported_by` 标记的旧工具导入信。
- **选择备份对比 / 修复时间**：支持 `.soul`、Olivia 信件备份和原版 `letter_pairs.json`。同时展示双方正文和时间；没有时间的备份只做对比。
- 每项默认“保持原样”。选择处理方式并点击“应用所选”，确认后保存。每页 30 项，翻页前先应用本页选择。
- 收起的信件和修复过的时间会出现在“已整理 · 可恢复”中，可以恢复该封信整理前的显示和时间。

近似正文只作提示，不能自动覆盖正文或按相似程度套用日期。源文件中同一正文对应多个日期时不猜测日期。完全相同的去信和回信才允许依据备份修复时间，同一分钟内保持源文件顺序。没有记录的日期不替换成导入日期。

清理采用可恢复的收起方式，不永久删除原信件、音视频、记忆档案或关系状态。正在生成正文或媒体的信件不参与整理。整理不调用模型，不产生生成费用。导入新信件仍使用原导入入口及其关系评估说明。

大量信件的完全重复检查覆盖全部；近似比较最多执行 20,000 次，超出时明确提示部分近似检查未完成。正文预览每侧每段最多 400 字，可点击“查看完整正文”。

## 持久化和并发

`state.json.letter_maintenance` 只保存显示覆盖项，键为信件来源、ID 和双方正文的 SHA-256，值为收起标记或修复日期/源顺序。数据变化后的信件不会继承旧正文的收起标记。使用现有原子状态写入和备份流程；不停止客户端、不直接修改 SQLite 原档案、不移除只读触发器。

预览包含当前信件及整理状态的摘要 token。应用时持有已有记忆管理互斥锁，重新计算允许的操作；只接受预览中的操作 ID。预览失效返回 409，不写入。不能同时收起需要保留的两侧，也不能同时恢复并修改同一封信。状态写入失败不提交内存中的新显示状态。

导出使用整理后的可见信箱和修复日期；再次导入会同时检查原记录、修复后的记录和已收起记录，避免重新产生重复信件。原文检索和长期记忆读取继续使用原档案，不因信箱收起而遗忘。

## 验证

合成测试覆盖预览只读、确认门禁、过期预览、伪造操作、互斥冲突、写入失败、跨重启恢复、日期/排序、导出正文一致、原生已读状态、重复信和失败信恢复、分页与完整正文。独立浏览器验收使用真实 HTTP handler、临时 SQLite 和真实 `.soul` 文件选择；原 SQLite 记录保持不变。浏览器截图不等同于打包客户端验收。
